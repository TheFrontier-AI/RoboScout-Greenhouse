# สเปกภารกิจ

## กรอบพิกัด
ใช้กรอบท้องถิ่นของโรงเรือน (เมตร, Z ขึ้น): จุดกำเนิดกลางโรงเรือน, ประตูอยู่ด้าน +Y, ทางเดินวิ่งตามแกน Y
ตำแหน่งในทางเดินบอกเป็น (aisle_id, metre) โดย metre = 0 ที่หัวทางเดินฝั่งประตู เพิ่มขึ้นเข้าไปในโรงเรือน (ตรงกับ `r1-aisle-map.json` ของทีม web)

## ภารกิจ
1. `go_to(aisle_id, metre)` — ไปหยุดที่จุดในทางเดิน (เข้าทางเดินจากฝั่งประตูเสมอ)
2. `survey_aisle(aisle_id)` — เดินหน้าจากหัวทางเดินถึงท้าย (ส่งภาพทุก 0.5 ม.) แล้วถอยหลังออกจนพ้นหัวทางเดิน
3. `survey_house(house_id)` — ทำ `survey_aisle` ทุกทางเดินที่ผ่านได้ เรียงจากซ้ายไปขวา ย้ายทางเดินผ่านลานหน้าประตู (headland)
4. `return_to_dock()` — กลับแท่นชาร์จหน้าโรงเรือน

## สถานะ (state machine)
IDLE → ALIGN_AT_HEAD (ตั้งหัวหุ่นตรงทางเดิน ใช้ป้ายหัวแถว/LiDAR) → DRIVE_IN (เดินกลางทางเดิน) → [STOP_OBSTACLE ↺ รอจนทางว่าง]
→ AT_TARGET หรือ AT_END → REVERSE_OUT → AT_HEAD → TRANSIT_HEADLAND → ... → DOCK
ทุกสถานะมี e-stop และ "หยุดเมื่อ LiDAR เห็นสิ่งกีดขวางหน้า < 0.6 ม." เหนือกว่าคำสั่งอื่น

## กฎเดิน
- ความเร็วเดินหน้า ≤ 0.25 ม./วินาที, ถอยหลัง ≤ 0.15 ม./วินาที (ล้อรัศมี 0.127 ม. → ≤ 2.0 / 1.2 rad/s)
- รักษาตำแหน่งกลางทางเดิน: ความต่างระยะซ้าย–ขวาจาก LiDAR → แก้หัวหุ่น (ตัวควบคุมสัดส่วนที่จำกัดอัตราเลี้ยว)
- ห้ามกลับตัวในทางเดิน; การหมุนทำได้เฉพาะบนลานหน้าประตูที่มีที่ว่าง ≥ 1.2 ม.
- ทางเดินที่ช่องว่าง < กว้างหุ่น + 2×0.06 ม. ถือว่า "ผ่านไม่ได้" และรายงานกลับแทนการพยายามเข้า

## ปัญหาเปิดที่ต้องตัดสินใจ
- ทางเดินข้างของ tunnel-09 ในโมเดล 0.55 ม. ผ่านไม่ได้สำหรับ R180 (0.53 ม.) → ต้องวัดหน้างาน หรือปรับหุ่น
- พื้นที่หน้าประตูจริง (headland) ยังไม่ได้วัด: การย้ายทางเดินต้องการที่หมุนตัว
